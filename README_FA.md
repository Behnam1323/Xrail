# Railway Xray — VMess WebSocket TLS

## قابلیت‌ها
- اجرای Xray-core داخل Docker
- ساخت UUID خودکار
- تولید لینک `vmess://` در صفحه اصلی
- هدایت WebSocket در مسیر `/ray` از Nginx به Xray داخلی
- endpoint سلامت `/health`

## استقرار
1. محتویات این پروژه را در یک GitHub repository قرار دهید.
2. در Railway از **New Project → Deploy from GitHub Repo** استفاده کنید و مطمئن شوید Build با Dockerfile انجام می‌شود.
3. در بخش **Networking** برای سرویس، **Generate Domain** را بزنید و مطمئن شوید دامنه به پورت `8080` متصل است.
4. اگر متغیر `RAILWAY_PUBLIC_DOMAIN` خودکار تنظیم نشده، در Variables مقدار `PUBLIC_HOST` را برابر دامنه ساخته‌شده وارد کنید؛ بدون `https://`.
5. پس از Deploy، صفحه دامنه را باز کنید و کانفیگ جدید را از پنل کپی کنید.

## مسیریابی
Nginx روی پورت `8080` درخواست‌های عادی را به پنل Flask روی `8081` می‌فرستد و WebSocket در مسیر دقیق `/ray` را به Xray روی `127.0.0.1:10000` هدایت می‌کند. TLS عمومی در لبه Railway خاتمه می‌یابد؛ ارتباط داخلی بین Nginx و Xray بدون TLS است.

## نکات مهم
- پس از استقرار نسخه جدید، کانفیگ را دوباره از صفحه اصلی کپی/وارد کنید تا UUID و دامنه با سرویس هماهنگ باشد.
- UUID در `/tmp` ذخیره می‌شود و ممکن است پس از جایگزینی کانتینر تغییر کند؛ اگر کانفیگ قبلی ناگهان از کار افتاد، لینک جدید را بگیرید.
- این نمونه پنل مدیریت کاربر، سهمیه مصرف یا احراز هویت پنل ندارد. لینک صفحه اصلی شامل UUID است؛ آن را عمومی منتشر نکنید.
- این اصلاح مسیر `/ray` را داخل کانتینر فراهم می‌کند، اما موفقیت نهایی همچنان به درست بودن دامنه عمومی و تنظیم پورت `8080` در Railway بستگی دارد.
